# 恋爱杂志版 · 移动交互实施建议

已阅读新附件 `920943e9-ed7d-4444-82b9-64eb5a056707/pasted-text-1.txt`。本文件是实施前建议，不是新版本PASS；未修改游戏实现。

## 保留已验证的主线

开场选男/女 → 30幕每幕一次选择直接推进 → 一次性12人格长报告 → 分享。附件的20题示例服从用户当前30幕目标，不加中途解释、研究提示或确认按钮。保留140ms选中反馈、450ms总保护和 `event.detail > 1` 尾点击过滤。

## 版式与小屏

- 米白、黑、酒红；Serif只用于大标题与人格名，聊天、答案、数字使用Sans。手机答案建议14px以上，道具证据至少12px，命中区域至少现有53px。
- 轻动画控制在约140–220ms；reduced-motion下关闭。阶段变色只影响浅背景、装饰线和少量重点，不使正文对比度下降。
- 移除漫画式重边框、影子、贴纸大装饰，生活瞬间仍以聊天/票据/物件为核心。道具不能缩回8–10px或覆盖重要对话。
- 使用题目实际角色身份与普通头像，不以同一男主/女主承载30幕。优先手机、手、背影、房间等场景，头像保持轻量，不需要额外人物选择入口。
- 报告首屏只放命中的人格卡、短总结和三维雷达；雷达同时输出三个文本标签与数字，8底层指标和长报告继续向下阅读。
- 分享卡必须使用当前报告的同一人格ID、名称和指标，不能分享时随机重分类。保持PNG保存、复制链接、无法原生分享时的降级提示。

## 可见时间计时

1. 每题从按钮成为可答状态起计，排除新幕310ms防误触等待；首题从实际可答开始。
2. 以 `performance.now()` 累计页面可见区间。`visibilitychange / pagehide` 结束当前区间并保存本题累计；恢复可见与pageshow开始新段，不能把隐藏等待算到答案。
3. 刷新当前题应保留已累计时间；进入新题重置本题计时，不把上题/报告/分享时间带入。
4. 每条答案保存nullable时间。旧记录缺计时不是0ms，不能因此判直觉型；有效计时样本不足时显示“节奏未评估”，用内容指标得到本地分类。
5. 报告只描述本局答题节奏，不把“快”当成真正直觉能力或“慢”当成准确思考；建议用中位数或稳健统计避免单题长等待支配类型。

## 12人格 / 8指标 / 3维雷达

- 三者必须有明确的本地映射与可复跑分类；每项结果可追溯到实际选项、计分题和nullable计时。
- 12人格固定且全部可达；同一记录刷新/分享得到同一结果。长报告以当前命中类型为主，其他11种无需变成额外首页分支。
- 旧报告答案全部可继续生成；缺计时只能使速度维度未知，不能让报告为空或强制重测。

## AI可选增强

- 无配置时本地报告立即可读；请求超时、网络错误、非JSON、缺字段均不挡报告/分享。
- 固定人格、分数和雷达由本地规则生成，AI最多增强措辞；不能改类型/数字或编造恋爱经历。
- 私钥只放服务器。启用接口后的数据处理文案应与实际请求一致；默认无配置时不能发外部请求。

## 附件冲突点

“没有标准答案”和“男性群体更可能怎么想”与当前创作心声、无群体样本不同。杂志外观不能把作者设定包装成男女总体的科学比例。研究解释仍留终局，明确本局人格是趣味解读类型，分数是本局创作心声匹配。
